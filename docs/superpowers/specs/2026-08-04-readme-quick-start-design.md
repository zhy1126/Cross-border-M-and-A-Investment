# README 快速上手版设计

## 目标

将仓库首页改造成面向 Skill 使用者的快速入口。读者无需先理解内部文件结构，即可在一分钟内判断是否适用、了解主要能力、复制示例指令并开始使用。

## 目标读者

- 处理中国投资并购事项的律师、法务、投资及交易团队；
- 希望调用 Codex Skill 完成结构、尽调、条款、审批或谈判任务的使用者；
- 不以维护源码或扩展法域的开发者为主要读者。

## 信息架构

README 按以下顺序组织：

1. **首屏定位**：仓库名称、一句话价值主张、当前版本状态及关键数据；
2. **适用场景**：用具体交易问题帮助读者判断何时调用；
3. **能力地图**：用表格展示结构设计、尽调、文件条款、审批、谈判、交割后六类能力；
4. **三条交易路由**：解释 `L-CONTROL`、`P-EQUITY`、`P-ASSET`；
5. **工作架构**：用一张简洁 Mermaid 流程图说明从输入到交付的处理过程；
6. **示例指令**：提供五组可直接复制的中文提示词；
7. **输出示例**：展示首页元数据和单个 Issue 闭环的精简样例；
8. **安装与验证**：保留最短可执行命令；
9. **边界**：说明法源时点、外国法、专业判断和 MNPI 限制。

## 能力地图内容

| 能力 | 典型任务 | 主要输出 |
|---|---|---|
| 交易结构 | 上市控制权、非上市公司股权、资产交易、分步与组合交易 | 结构备忘录、方案比较、时间线 |
| 法律尽调 | 红旗、完整尽调、Major Issues、更新尽调 | Issue Log、风险—条款矩阵 |
| 文件与条款 | SPA/APA、股份转让、认购、披露、赔偿与责任限制 | 审阅意见、条款建议、跨文件核验 |
| 审批与交割 | 反垄断、国资、外资、ODI/外汇、数据与出口管制 | 分阶段审批矩阵、交割清单 |
| 谈判 | 买方默认、卖方切换、give/get、fallback、walk-away | 谈判计划、让步顺序、升级点 |
| 控制与并表接口 | 法律控制、治理控制、经营者集中控制、会计控制 | 控制分析、审计师确认材料清单 |

## 工作架构

流程图只呈现使用者需要理解的五层：

`用户事项 → 入项与路由 → 法源/场景 Playbook → 问题—条款闭环 → 交付物与完成状态`

其中：

- 入项层确认立场、阶段、法域、材料和保密等级；
- 路由层选择三种交易路线，可在真实混合交易中叠加；
- 知识层区分现行硬法源、历史/草案、案例材料和市场 Playbook；
- 分析层把事实映射至价格、CP、保证、赔偿、承诺、终止或交割后行动；
- 输出层明确 `passed`、`passed_with_limitations` 或 `blocked`。

## 示例指令

提供五类示例：

1. A股29%协议转让、董事会控制与并表；
2. 非上市公司买方红旗尽调；
3. SPA重大条款审阅及问题—条款映射；
4. 卖方赔偿责任限制谈判；
5. 中国国企境外收购的中国侧审批与资金出境。

所有示例均使用中文自然语言，不要求读者理解路由代码。

## 输出示例

输出示例保持简短，展示：

- 事项、路由、立场、as-of、材料范围、假设、法域和完成状态；
- 一个 Issue 的已确认事实、待确认事实、规则、风险、主方案、fallback、责任人和关闭证据；
- 条件式结论，不制造审批、并表或外国法确定性。

## 表达和视觉约束

- 中文为主，保留必要的交易英语缩写；
- 首屏不堆叠完整目录或法律清单；
- 使用一张 Mermaid 架构图和两至三张紧凑表格；
- 不使用未经验证的市场比例、宣传性最高级或“替代律师”等表述；
- 法源数量、测试数量和核验日期必须从当前仓库状态取得，避免手写失真；
- README 控制在可快速扫描的长度，详细内部说明仍留在 Skill references 中。

## 验收标准

1. 新读者能在一分钟内说明 Skill 的适用范围、默认立场和三条路线；
2. 至少五组示例指令可直接复制使用；
3. 能从架构图理解法源分层与问题—条款闭环；
4. 安装和三条验证命令准确可运行；
5. 不把历史文章、案例或外国法接口表述为现行中国硬法源；
6. README 与当前 Skill 的文件、能力、44条法源记录和18项测试保持一致。
