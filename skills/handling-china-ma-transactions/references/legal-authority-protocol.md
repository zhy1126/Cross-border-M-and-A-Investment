# 法源与时效协议

## 1. 四层来源，不得混写

1. **硬法源**：法律、行政法规、司法解释、部门规章及具规范效力的正式文件；可以支持法律结论。
2. **监管与案例材料**：交易所问询/指南、执法决定、公告、项目文件和正式口径；只证明特定监管观察、个案事实或程序。
3. **历史/草案材料**：旧法、已废止文件、征求意见稿；只用于交易时点分析或趋势提示。
4. **市场 playbook**：谈判经验、模型条款、统计和作者观点；用于选项设计，不能表述为法律要求。

文章来源和泰胜风能表格属于第2/3层。它们提出应检查的问题，不自动生成现行结论。

## 2. 先检索索引，再打开官方原文

使用脚本缩小范围：

```bash
python3 scripts/legal_authority_lookup.py --route L-CONTROL --effective-only
python3 scripts/legal_authority_lookup.py --topic merger-control --as-of 2026-08-04 --json
python3 scripts/legal_authority_lookup.py --topic listed-issuance --freshness-days 30
```

索引是导航和版本控制，不替代原文。涉及签署、备案/申报、公告、董事会/股东会材料、交割或对外法律意见时，必须在同一任务中打开相关机关的官方页面/附件复核，并记录核验日期。

每条 authority 记录必须同时保存条级 `pinpoint`、可操作的 `proposition` 和非空 `short_excerpt`。`short_excerpt` 只摘录官方文本中支撑命题所必需的最少文字，不能用模型概括冒充引文；命题覆盖多个制度时，仍须在同一任务中按所列条文逐项复核。

## 3. 法源选择顺序

1. 识别交易日期、市场/板块、取得路径和主体身份；
2. 用 `--as-of` 选择当时已生效且尚未废止/替代的版本；
3. 打开官方正文和修法决定，核对条号、例外、过渡和附件；
4. 分别标记法律要求、监管观察、案例和建议；
5. 把草案作为平行分支，不得覆盖有效版本；
6. 数字阈值、期限、价格公式和锁定期必须有 pinpoint；
7. 如果官方状态或整合文本不清，标记 `status-unverified` 并限制结论。

## 4. 状态含义

- `effective`：截至最后核验日已生效；具体交易仍需按 `as-of` 检查。
- `not-yet-effective`：已公布但尚未施行。
- `draft`：征求意见或草案，不得作为现行法。
- `repealed`：已废止/被替代；只可用于历史分析。
- `status-unverified`：无法从官方来源确认；不得支持确定结论。

“现行”不是永久属性。特别是交易所规则、负面清单、行业许可、登记材料和跨境审批，索引超过30日或任务高风险时必须实时复核；一般法规索引超过90日也应刷新。

## 5. 引用格式

每个重要命题使用：

```text
[层级｜状态｜核验日] 文件名称（机关，文号），条/款/附件定位：规范命题。官方链接。
```

示例标签：`[硬法源｜effective｜2026-08-04]`、`[案例材料｜historical case｜2022-03-21]`。

短摘只保留支撑命题所需的最少文字；不得以长篇复制代替分析。若官方页面与附件冲突，优先核查盖章/发布附件并披露冲突。

## 6. 版本链

修法决定、整合文本和解释文件分别保存，用 `supersedes` / `superseded_by` 连接。历史交易使用当时版本；当前交易不得因文章或模板中仍有旧条号而沿用。

高风险示例：

- 旧《公司法》第141条不得作为当前上市公司董事/高管转股限制依据；应查现行条文与交易所规则。
- 旧“非公开发行”办法、实施细则和战略投资者问答不得替代注册制规则。
- 2018年投票权委托征求意见材料不是现行规范。
- 2026年7月再融资征求意见稿在正式生效前只能标记为草案。

## 7. 法域边界

首版硬法源仅覆盖中国法。中国买方收购境外目标时，继续完成中国侧 ODI、外汇、国资、经营者集中、数据/技术出口等分析；目标所在地反垄断、投资审查、劳动、税务和行业法由当地合资格律师/顾问确认。未建立该法域的版本化硬法源库前，不检索、不引用、不计算也不写出外国申报阈值，即使附免责声明也不例外；只列触发因素、所需事实、当地律师责任和交割交付物。

## 8. 验证

交付前运行：

```bash
python3 scripts/validate_legal_authorities.py
```

验证通过只证明数据结构和内部一致性，不证明每项交易结论完成了同任务官方复核。
