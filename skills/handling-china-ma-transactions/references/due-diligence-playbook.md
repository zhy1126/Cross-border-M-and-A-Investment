## 1. 目标与边界

尽调服务于交易决定，不是资料摘要。默认买方应验证“能否买、买什么、以什么价格、满足什么条件、如何追偿”；卖方模式应组织预尽调、修复、披露和可控开放。

适用 `L-CONTROL`、`P-EQUITY` 和 `P-ASSET`。三条路由共用问题—条款闭环；`L-CONTROL` 还必须执行下列公开市场与监管增量核查。纯少数股权融资不因使用尽调清单而成为并购，应转交 PE/VC 融资能力。

所有发现使用四层标记：

- `[事实]`：文件名/版本/日期/数据室索引/访谈对象；区分已证实、管理层陈述和未提供。
- `[法律]`：当前官方来源、适用时间和待专项核验；不得用文章或案例替代。
- `[风险]`：影响对象、概率条件、金额/时间/控制后果及可补救性。
- `[策略]`：结构、价格、条件、承诺、保证、赔偿、交割证据或退出动作。

不因资料缺失直接断言违法；写为“未取得支持文件，无法确认”，并说明取得何种证据可关闭问题。

## 2. 启动和信息治理

### 2.1 范围卡

记录：交易路径、立场、目标/资产范围、基准日、材料语言、相关主体、关键法域、行业、国资/外资/数据/反垄断等监管身份、用户设定的重要性阈值、签署与交割时间。

### 2.2 保密与访问

- 核对 NDA 的允许用途、接收人、顾问、融资方、监管披露、返还销毁和违约救济。
- 数据室按最小权限分层，保留上传、替换、下载和问答日志。
- 竞争敏感信息采用 clean team、聚合/脱敏、延迟开放或第三方核验；不得让业务团队提前获得可协调市场行为的信息。
- 个人信息、重要数据或跨境访问先做数据角色、目的、必要性和传输路径核验；不得把“并购尽调”当作当然处理依据。
- 外部搜索不得输入未公告交易名、价格、客户/员工清单、原始合同或其他机密事实。

### 2.3 请求清单

请求项应说明期间、主体、格式、优先级和用途。建立状态：已提供、部分提供、声称不适用、待提供、拒绝提供、被替换。保留版本差异，不接受“已上传”作为完成证明。

卖方模式先做红旗扫描、资料清洗和特权/商业敏感审查；不得删除不利文件或以预尽调替代真实披露。

## 3. 工作流与专题清单

### 3.1 三层流程

1. 红旗层：控制、权属、许可、重大责任、关键合同、资金和监管路径。
2. 完整层：按专题验证历史、现状及交割后可运行性。
3. 更新层：签署日前、交割日前更新新文件、争议、违约、监管和经营变化。

### 3.2 专题清单

| 专题 | 核心问题 | 主要输出 |
|---|---|---|
| 主体与治理 | 设立存续、章程、授权、股东权利、控制链 | 权属/授权图、同意清单 |
| 股权与资本 | 出资、代持、质押冻结、期权、优先权 | fully diluted 表、权利负担清单 |
| 业务与许可 | 经营范围、牌照、地域/主体限制、整改 | 许可矩阵、关键条件 |
| 重大合同 | 控制权/转让限制、排他、最惠、违约、终止 | 同意矩阵、流失风险 |
| 融资与担保 | 债务、加速到期、交叉违约、担保、资金池 | 偿债/解除安排 |
| 资产与不动产 | 权属、用途、负担、租赁、设备存货 | 权属例外、转移清单 |
| 知识产权/IT | 权属链、许可、职务成果、开源、系统依赖 | IP/系统风险及迁移方案 |
| 数据与网安 | 数据清单、角色、授权、安全事件、跨境 | 数据问题表、隔离/整改动作 |
| 劳动与激励 | 合同、社保、工时、派遣、竞业、激励、工伤 | 人员责任与留任方案 |
| 税务 | 申报、优惠、关联交易、稽查、重组接口 | 税务专项转介和条款需求 |
| 财务与会计 | 收入质量、净债务、营运资金、或有事项 | 价格调整输入；不替代审计 |
| 诉讼与合规 | 争议、处罚、反商业贿赂、制裁/出口管制接口 | 责任区间、专项核验 |
| 环境与安全 | 许可、排放、土壤、危废、事故整改 | 修复/赔偿/交割条件 |
| 关联交易 | 依赖、定价、担保、资金占用、分离 | 清理或持续安排 |
| 保险 | 承保范围、除外、索赔史、尾险 | 保障缺口与续保动作 |

上市公司、国资、外资、反垄断、行业准入、安全审查或跨境数据等触发项，应转监管叠加模块，并标明是否已用现行官方来源核验。

### 3.3 `L-CONTROL` 上市交易增量核查

在通用专题清单之上，按拟采用的控制取得路径建立一张相互勾稽的上市交易工作表：

| 覆盖面 | 最低核查动作 | 条款/文件接口 |
|---|---|---|
| 公开资料与 MNPI | 先以公告、定期报告、监管问询等公开资料建立基线；对非公开信息标记 MNPI，限制知悉范围、搜索和对外传输，并核查停牌、保密及披露接口 | NDA、clean-team 规则、公告前信息隔离和披露责任 |
| 股份取得路径 | 区分存量股份转让与发行新股，核查主体、比例、价格、锁定/转让限制、付款和控制移交是否一致 | 股份转让协议、股份认购协议及其附表/交割文件 |
| 公法文件 | 识别要约收购、权益变动、收购报告、发行/交易所审核等适用文件及其时点；不得用交易协议替代法定披露或监管程序 | 要约/权益变动文件、公告、申请/回复及财务顾问文件 |
| 控制与治理 | 穿透核查表决权、董事提名/席位、委托或放弃、章程及一致行动等安排，并分别分析证券法控制、公司治理与会计并表 | 表决权/治理安排、章程、股东会/董事会文件及控制移交证据 |
| 硬门与交割 | 将适用批准、审核、注册、申报、信息披露、要约或 standstill 等要求分配至正确阶段 | 法定或监管硬门不得以合同约定豁免；条款只能如实配置责任、时点、失败后果及合法范围内的受益方豁免 |

不得因公开资料已披露而省略核验，也不得因尽调发现已知问题而仅以一般保证覆盖；公开资料、数据室材料、协议披露和法定公告之间的矛盾须单列并升级。

## 4. 问题分级

不要仅用“高/中/低”。每项记录：

- 阻断性：是否可能阻止签署、生效、交割或取得控制/核心资产；
- 价值性：是否改变价格、净债务、营运资金或协同；
- 责任性：历史损失、持续损失、第三方索赔或监管后果；
- 可补救性：交割前可修复、交割后可承诺、仅可定价或应退出；
- 时效性：审批、同意、整改和诉讼期限；
- 证据强度：已验证、部分验证、单方陈述、材料缺失。

重大问题清单建议字段：`ID｜标签｜事实与来源｜待核法律｜风险情景｜金额/时间范围｜建议动作｜对应条款｜责任人｜截止日｜状态`。

即使用户只要求“风险清单”或时间很紧，每一行也不得省略责任人、状态和关闭证据；未知时写“待指定”，不能删列。

走开事项通常包括：核心权属无法证明且无可行替代、关键许可无法取得/维持、目标业务边界不可执行、重大非法目的、风险无法量化且无可执行追偿保障。是否走开须结合价格、结构和用户风险偏好，不应机械结论。

## 5. 问题—条款闭环

每项问题按下列顺序处理：

`事实 → 适用规则核验 → 风险情景 → 交易决定 → 文件条款 → 交割证据 → 交割后监控/索赔`

| 风险类型 | 首选交易动作 | 常见条款 | 关闭证据 |
|---|---|---|---|
| 核心权属瑕疵 | 修复后再交割；否则排除/降价/退出 | 条件先决、权属保证、专项赔偿、托管 | 登记、解除负担、第三方确认 |
| 关键同意缺失 | 获取同意或合法替代 | 条件、合理努力、延迟/部分交割、长停日 | 正式同意或新合同 |
| 金额可量化负债 | 价格扣减或清偿 | 净债务调整、特定扣款、清偿交付 | 付款/解除证明 |
| 金额不确定历史风险 | 隔离、专项保护 | 专项赔偿、托管/保函、存续期 | 风险关闭或保障到位 |
| 交割后可整改 | 计划化承诺 | 交割后承诺、里程碑、留置/分期 | 验收、报告、监管确认 |
| 信息仍缺失 | 补充尽调或风险分配 | 信息条件、保证、披露限制、退出权 | 完整材料和更新证书 |
| 经营波动 | 定价或交割保护 | 锁箱保护、完工账、日常经营承诺、MAC | 交割报表、重申/更新 |

禁止空泛写法：“建议在协议中予以约定”。必须写明由谁、何时、达到什么标准、如何证明、失败后果和是否可豁免。

保证不能替代已知问题处理；已知问题通常应进入价格、交割条件、专项赔偿或明确承诺。披露不能自动消除风险，应按协议定义判断其免责效果。

## 6. 更新、交割和交付标准

### 更新机制

- 设材料截止日和更新频率；对新增文件保留差异记录。
- 签署前复核授权、重大变化、关键同意和监管路径。
- 交割前做 bring-down：保证重申、诉讼/处罚、核心合同、员工、数据事件、财务与运营异常。
- 对未关闭问题注明 owner、期限、条款保护和接受风险的授权人。

### 交付层级

1. 红旗快报：仅列交易决定所需事项和立即动作。
2. 完整报告：事实、法律待核、风险、建议及附件索引。
3. 问题—条款矩阵：供 SPA/APA 起草和谈判。
4. 条件/交割清单：责任人、证据、截止日和状态。
5. 交割后台账：承诺、整合、保障到期和索赔期限。

### 完成状态

- `passed`：范围内材料和官方规则已按约定时点核验，重大问题已形成交易处理。
- `passed_with_limitations`：存在明确列示的资料、专业或规则核验缺口，但可给条件式建议。
- `blocked`：缺口影响核心权属、许可、边界或可执行性，无法负责任地提出完成建议。

不得因出具报告而把未答复、未核验或交割后待办标为关闭。
